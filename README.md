# Refmatrix — панель управления

Адаптивный интерфейс на React + Vite с Supabase Auth и PostgreSQL. Включает вход/регистрацию, панель главного администратора, ссылки на оплату, ручное подтверждение платежа, список клиентов и настройки СБП.

## Важно перед публикацией

- Интерфейс сейчас включает демонстрационные строки, если Supabase не подключён. Это **не настоящая обработка платежей**.
- Для реального входа и общей базы нужен Supabase. GitHub Pages сам по себе не предоставляет серверную базу данных.
- СБП здесь — показ реквизитов и ручное подтверждение администратором. Для автоматического определения поступления денег подключите легального платёжного провайдера с API/webhooks.
- Платёжные ссылки в этом стартовом шаблоне не являются полноценной публичной страницей оплаты; перед запуском в продакшен добавьте отдельный маршрут `/pay/:id`, проверку ссылки и безопасный серверный поток оплаты.
- Не храните секреты и service-role ключи в клиентском коде или репозитории.

## Запуск локально

1. Установите Node.js 20+.
2. В терминале в папке проекта выполните:
   ```bash
   npm install
   cp .env.example .env.local
   npm run dev
   ```
3. Создайте проект на [Supabase](https://supabase.com/).
4. В настройках проекта Supabase скопируйте Project URL и anon/public key в `.env.local`:
   ```env
   VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
   VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
   ```
5. В Supabase откройте **SQL Editor**, вставьте содержимое `supabase/schema.sql` и выполните.
6. Зарегистрируйте свой аккаунт через Refmatrix. В SQL Editor назначьте его главным администратором:
   ```sql
   update public.profiles
   set role = 'admin', is_active = true
   where email = 'ВАШ_EMAIL';
   ```
   Используйте именно свой email. Никогда не добавляйте публичную регистрацию с ролью admin.
7. Обновите страницу и войдите. Новые регистрации получают роль клиента и ждут активации после подтверждения оплаты.

## Деплой через GitHub

Рекомендуемый вариант — GitHub + Vercel (или Netlify), а Supabase оставить базой данных.

1. Создайте репозиторий GitHub и загрузите файлы проекта.
2. Импортируйте репозиторий в Vercel.
3. В Project Settings → Environment Variables добавьте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.
4. Выполните Deploy.
5. В Supabase → Authentication → URL Configuration укажите production URL сайта в Site URL и разрешённых Redirect URLs.

GitHub Pages может разместить только статическую сборку и не заменит Supabase. Для публикации через GitHub Pages настройте Vite `base` под имя репозитория и workflow сборки.

## Роли и доступ

- `admin` — просмотр клиентов и ссылок, ручное подтверждение оплат.
- `customer` — личные ссылки и собственные платёжные реквизиты; до активации аккаунт видит экран ожидания.
- Таблицы защищены Row Level Security (RLS). Перед боевым использованием обязательно протестируйте политики под двумя разными аккаунтами.

## Перед запуском для реальных клиентов

- Добавить публичную страницу оплаты по токену с ограниченным доступом и сроком действия.
- Связать ссылку с целевым аккаунтом/планом, чтобы подтверждение платежа активировало именно этого клиента. Не включайте `is_active` для владельца ссылки автоматически без проверки получателя.
- Сделать журнал действий администратора, защиту от перебора паролей, CAPTCHA/лимиты регистрации и восстановление пароля.
- Для автоматической оплаты — серверные API/webhooks провайдера, идемпотентность, проверку подписи вебхука и сверку суммы/заказа.
- Проверить применимые требования к персональным данным, переводам и приёму платежей.
